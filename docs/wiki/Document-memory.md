# Document memory

Besides the "distilled" memory (episodes → facts), MimirSynth stores **documents**: manuals, notes, wiki pages, PDFs. This page explains how it works inside and how to get the most from it. Usage is in [[Knowledge]].

## Principles
1. **The document is the source of truth.** It is indexed and **cited**, but **not turned into facts** in the graph. This avoids noise, duplicates and the cost of using an LLM on a long text.
2. **Always with provenance.** Every returned passage carries its source, title, section, link or path and sync date.
3. **Per brain.** Documents belong to a brain: same roles, same isolation, same audit.
4. **Content is data, not instructions.** Recall marks passages as quotes.

## How a document is indexed
1. The **original is stored** in the store volume (or, for a folder, referenced without copying).
2. The **text is extracted** (Markdown, plain text, HTML, PDF, and Office: Word, PowerPoint, Excel and OpenDocument text).
3. The **secret detector** looks for credentials in the text and, depending on the brain's policy, masks them or leaves the document unindexed (see below).
4. If the same text (ignoring case and spacing) is **already indexed** in another document of the brain, the document is marked **duplicate** and stops here (see below).
5. It is **chunked by headings and sections**, keeping the heading path ("Installation › Requirements").
6. The **embeddings** of each chunk are computed and stored with the text for full-text search.
7. When the document changes, the chunks are **replaced all at once**: a document is never left without an index.
Everything runs in the background as a [job](Jobs).

## How it is searched
Search is **hybrid**: it mixes similarity by meaning (vectors) with word matching (full text) and fuses both lists. It works with natural-language questions and with exact terms (codes, names).

## What the agent receives in recall
In agents' **recall** (REST API and the MCP `recall` tool), document passages go in a separate "Documents" section with a small budget (2 passages, ~600 tokens, 0.6 s) so they do not displace the facts:
- **Only if relevant:** below a similarity threshold nothing is added, so a question unrelated to documents costs no tokens.
- **No repeated passages:** when the same text appears in two documents (the same note in two sources), or in the brain and in a brain that lends it its documents ([federation](https://github.com/MimirSynth/mimirsynth/blob/main/docs/FEDERATION.md)), only the first copy is kept. The budget always goes to **different** passages.
- **Never slower:** the document search runs in parallel with the facts search, with its own time limit; if it overruns, the section is left out.
- **Can be disabled** per request (`docs=0`), and the agent can ask afterwards for more context of a passage or for the original file. See [[Connect agents]].

The budget and the threshold are adjusted in [[Recall and ingestion]].

## Duplicate documents
A document whose extracted text matches one already indexed in the brain is marked **duplicate**: it is neither chunked nor embedded, so the same content never takes two places in the index or in recall. The rules:
- The **oldest** copy is the one indexed. If it is deleted, leaves its source, changes or cannot be indexed, the oldest duplicate is indexed in its place.
- Deduplication is **per brain**. Across brains, federation already labels where each passage comes from.
- Documents indexed before this check existed are reviewed with **Find duplicates** in [[Knowledge]] (brain administrators). Nothing is deleted at the source.

## Secrets in documents
Before chunking, the secret detector looks for credentials: cloud and AI provider keys, GitHub, GitLab, Slack, npm and Hugging Face tokens, PEM private keys, JWTs, `Authorization` headers, passwords in URLs… A random-looking value assigned to `password`, `secret` or `token` counts only as a **possible** secret and is just flagged. The brain's policy (Administration → Brain access → **Secrets**) decides what happens to the certain ones:
- **Mask** (default): they are replaced in the indexed text, so they never reach the chunks, the vectors or the agents.
- **Block**: the document is not indexed and shows an error.
- **Only warn**: nothing is changed.

The **downloadable original is never modified**. The detected value is never stored in the audit log, the logs or the API responses. Exceptions and **Scan what is already stored** are in the same section of Administration.

## File store
Originals live on a **stack volume** (`MIMIRSYNTH_DOC_STORE`), **not** in PostgreSQL: the database only stores the reference, the chunked text and the vectors. Paths are generated by the server (never from a user-supplied name). The volume **must be part of backups**; the PostgreSQL index can be regenerated from it ([[Upgrade and backups]]).

## Source types
| Source | What it is | Who manages it |
|---|---|---|
| **Uploads** | Files dragged into the web | Contributor or higher |
| **Folder** | A directory mounted **read-only**; rescanned every N minutes | Brain administrator (roots: instance administrator) |
| **Wiki** | A wiki through its API, read-only: Outline, Confluence or Notion | Instance administrator |

### Folder scanning
It detects **new, changed and disappeared** files by size, date and hash. If the folder appears empty in a scheduled scan, it fails without deleting anything (protection against unmounted volumes). An Obsidian vault needs no adapter: use it as a folder.

### Wikis and adapters
A wiki is connected through an **adapter**: a small class that lists the collections and returns the pages. The connection form builds itself from the fields the adapter declares.

| Adapter | Collections | State |
|---|---|---|
| **Outline** | Collections | Tested against a real instance |
| **Confluence** (Cloud and Data Center) | Spaces | Written against the documented API and covered by tests; **not yet validated against a live instance** |
| **Notion** | Databases shared with the integration, plus loose pages | Written against the documented API and covered by tests; **not yet validated against a live instance** |

Docmost is not supported: it has no documented public API yet. If you use Confluence or Notion, check the first scan and report any problem.

Sync is **incremental**: pages are compared by modification date and only new or changed ones are downloaded, which keeps rescans cheap even when each page costs a request (Notion). If the wiki fails halfway, the scan stops without deleting anything. To write a new adapter (read-only and stateless), see "How to add another wiki" in [`docs/DOCUMENTS.md`](https://github.com/MimirSynth/mimirsynth/blob/main/docs/DOCUMENTS.md).

## Permissions
| Action | Role |
|---|---|
| Search, open, view context, download the original | reader |
| Upload files, promote a passage to memory, delete the files you uploaded | contributor |
| Reindex, delete any uploaded document, find duplicates, manage folder sources | brain administrator |
| Add wikis, change their collections and credentials | instance administrator |
Every action is recorded in the [[Audit log]].

## From document to memory
When a passage holds something you want the system to **remember and reason about** (not just quote), use **Promote to memory**: it creates a [proposal](Proposals) with the text (which you can edit) and its provenance. If you are a curator it is ingested; otherwise it goes into quarantine. The document does not change.

## Limits and tips
- **Scanned** PDFs (image only) have no text to index.
- Very long documents are bounded by *Maximum text extracted* ([[Folders and limits]]).
- Documents with a lot of junk (menus, repeated headers) make search worse: clean the source if you can.
- Changing the embedding model (Administration → Embeddings, see [[AI providers]]) recomputes the document vectors too.
